## Current Milestone

**Ultimate feedback, per-Duo refocus & Duo hero cards (2026-07-29)** — Designer-directed session. Everything parses and imports clean; **no visual verification** — the HUD restructure below is the whole point of the pass and needs a Designer playtest.

- **Spent Ultimate cards get out of the way.** Activation was near-invisible: the only feedback was a button relabelling itself to USED behind a card that kept covering the battlefield. `BattleManager.activate_ultimate` now calls `BattleHUD.show_ultimate_used`, a centre-screen gold flash (pop in, 2s hold, 0.7s fade) that names the Duo and its Ultimate; it's a separate control from the objective-buff banner, which is a countdown readout rather than a one-shot event. `DuoUltimateBar` gives the spent card a pop then fades it to `SPENT_ALPHA` 0.12 — kept in the bar so the layout doesn't jump, but `mouse_filter = IGNORE` **and** `focus_mode = NONE`, because a disabled Button still emits `mouse_entered` and would keep firing UIStyle's hover wiggle on an almost-invisible card.
- **Per-Duo refocus, 1 per Duo per level.** `FocusPing` existed as a script but **was never instantiated anywhere** — refocus was dead code, and this is the first build where it reaches the player. Rewritten from one global 3-charge marker to per-Duo state keyed by `pair_id` (`_pings`/`_timers`/`_used`, one `_armed` Duo at a time). Two clicks: press the Duo's REFOCUS button, then left-click inside the field ellipse. Right-click or re-pressing cancels an *armed* refocus for free; an off-field click costs nothing. Created once the first wave lands (`BattleManager._spawn_focus_ping`), deliberately **not** during deploy, where its left-click would fight the placement clicks. Markers draw in the Duo's accent (gold A / navy B). `Hero` passes `hero_name` to all three consumers (goal override, `_ping_targets_villain`, `_focus_ping_bonus`) so each hero only answers its own Duo's marker.
- **Markers expire after 5s** (`FocusPing.DURATION`). It's a rally order, not a new home — long enough to pull a Duo across the field and commit their fire, short enough that they don't camp the spot for the level. The ring drains clockwise from the top and dims as it runs out. Expiry never refunds the charge.
- **Hero cards are grouped by Duo and share one refocus button.** `BattleHUD.setup_heroes` now builds one bordered Duo group per pairing (gold A / navy B) holding both members' cards with the REFOCUS button centered *between* them — the position that reads as belonging to the pair. Idempotent, so it doubles as the rebuild path after the start-of-level reshuffle (`rebuild_duo_ultimate_bar` calls it; safe because the reshuffle resolves before deploy, when no `Hero` exists). A hero in the party but in no valid pairing still gets a plain ungrouped card, so a broken pairing can't make a hero vanish. The button fades like a spent Ultimate card, but **on expiry, not on the spending click** — the countdown is live information the player is watching.
- **Vertical budget measured, not estimated.** Four cards plus two button rows overran the 1080 canvas. Measured headlessly: a real card is **200px** (the scene's 249 includes the second-ability row, permanently hidden since `Hero.second_ability_name()` always returns `""`); button row 37px; column **920px, bottom edge y=1050**. Paid for by three trims that are all load-bearing — button vertical padding 12→4 (`REFOCUS_BUTTON_PAD_Y`), hero card content margins 10→8, `HeroPanelsRoot` y 140→130 (as high as it goes; BackButton ends at 124) and separation 8→6.
- **Buff pills sit side by side** instead of one per line, which was growing the card downward into space that no longer exists. Safe only because `HeroPanelUI._ready` now turns word-wrap off, `fit_content` off and `clip_contents` on for that row — the newline-stacking existed because space-joining used to wrap and overlap the fixed-height rect.
- **Bug caught by the measurement run:** `get_theme_stylebox_override()` is not in the Godot API. Now `has_theme_stylebox_override()` + `get_theme_stylebox()`, and the guard is not optional — `get_theme_stylebox` falls back to the project theme's *shared* StyleBox when there's no override, so editing it would silently re-pad every button in the game.
- **A run now requires BOTH Duos.** `PrepMenu._refresh` gated START RUN on `not RunState.selected_heroes().is_empty()`; `_sync_party_from_slots` refuses a *half*-filled Duo but happily builds a 2-hero party from one *complete* one, so a single Duo lit the button. Now `_both_duos_ready()` (`duo_pairings.size() == 2`). Deliberately **not** `has_valid_duo_pairings(draft_offer)`, which also demands the pairing cover the whole offered roster — equivalent today, but it would make START RUN unreachable the moment a 5th hero is unlocked. The status text beside the Duo boxes now leads with the blocker and names who's left to place.
- **Known gap:** nothing stops a *mid-run* party from dropping to one Duo through deaths — how the per-Duo Ultimate and refocus systems read a run down to two survivors in one pairing is unverified.
- **Next:** playtest, in this order — (1) the Duo-grouped hero cards at real size, especially that the 4-card column doesn't clip at the bottom, (2) whether 5s is the right rally window and whether one refocus per Duo is enough of a lever, (3) buff pills with 2–3 buffs on one hero, (4) the Ultimate banner and card fade, (5) START RUN gating with one Duo, then both, then CLEAR PAIRING.

## Previous Milestone

**Cover, readability & itch prep pass (2026-07-28)** — Designer-directed session. Everything compiles and boots headless (title + level 2); **no visual verification** — layout/feel items below all need a Designer playtest.

- **Projectiles are blocked by obstacles.** `Projectile` ignored the field entirely. It now dies silently on contact with any `LaneField.obstacles`/`dynamic_obstacles` (new `blocks_projectile`), reusing the same `SpriteFootprint.radius_toward` oval the collision/steering code uses, so a shot is stopped by exactly the shape a unit is pushed out of. Decorative scenery, lakes and spike pits deliberately do **not** block — they're ground, not cover. Ranged units hold fire and reposition rather than plinking a rock (`has_line_of_sight`, with `LOS_END_SLACK` 28px trimmed off both ends so a shooter or target standing flush against a rock isn't read as permanently blocked). Pinned shooters (HeroClone, LaneSpawnPoint) can't reposition, so they wait for the target to step clear.
- **Font swapped: DrawFont → Caveat Brush** (Pablo Impallari / Google Fonts, **SIL OFL** — `CaveatBrush-OFL.txt` ships beside the .ttf and must stay in the build). Designer asked for Brush Script MT; that's a Monotype face bundled with Office, isn't installed here, and embedding it in an itch build isn't covered by its EULA — Caveat Brush was picked as a legal lookalike that is also *more* legible, which was the actual complaint. **This fixed three latent HTML5 bugs:** DrawFont had only 140 glyphs and was missing every non-ASCII character the UI uses, including the em dash and the middle dot in shipped strings. On Windows `allow_system_fallback` was silently borrowing them from a system face; a browser has no system fonts, so all of those were headed for tofu. Caveat Brush (641 glyphs) covers `—`, `·`, `…`. Fallback is now **off**, so a missing glyph shows up on desktop instead of hiding until export. Rank pips moved `●`/`○` → `•`/`°` and "MAXED" `●` → `•` for the same reason. **Known gap:** `sprite_gallery.gd` uses `⊘ ✓ ❌`, none of which are in the face — dev tool, left alone, will render as boxes.
- **Duos can be rearranged between levels.** New `DuoRearrangeScreen` — a paused click-two-slots-to-swap overlay raised before deploy on every level after the first (`BattleManager._begin_deploy_setup`, which must resolve before `_compute_duos()` feeds the DeployController). Deliberately not the prep drag-and-drop panel: the party is fixed by then, so the only meaningful operation is exchanging two placed heroes. **Dead heroes keep their slots, greyed and unselectable** — `RunState.duo_wiped()` detects a fully-wiped Duo by name, and rebuilding pairings from the living only would drop it out of the array and silently break the single-lane rule. Swapping within one Duo is a real move: slot 0 is the leader. Boons stay keyed by pair id, so splitting a Duo parks its boons and re-forming it restores them (Designer's call).
- **Bug found and fixed in the above:** `BattleHUD._ready` builds the Duo Ultimate bar when the scene loads, *before* the reshuffle writes the new pairing — so the bar kept offering the old pair's Ultimates. `DuoUltimateBar.rebuild_cards()` re-derives them on confirm. Cards are freed with `free()`, not `queue_free()`, since the rebuild adds replacements the same frame.
- **Boon popup reordered.** Instruction now leads at heading size with the Duo/Ultimate name below, and both left the ACCENT gold (`#a8861a`) that read washed out on cream. Instruction is `INK`, subject is `GOOD` (forest `#1f7a33`) — a different hue at near-ink contrast, so "more contrast" and "less monocolored" don't fight. Cards keep gold borders.
- **Berserker fights in view of his lair.** His leash was anchored to his *spawn* point, which `VILLAIN_LAIR_OFFSET` puts 300px in front of the lair, so he could hold ground 300 + `leash_radius` 700 = **1000px** away — past the camera's ±960 half-view at default zoom, which is why the lair was never on screen. Now anchored to `LaneField.lair_pos`; worst case is 700 and fits. **`leash_radius` deliberately untouched** — territory is the same size, just centred on the thing it was named after. Side effect to watch: the fight sits ~300px closer to the lair, so the party can fall back slightly further before he disengages.
- **Duo Ultimate effects draw behind units and obstacles.** They were added to the caster's own `Heroes` container, which sits after `MinionSpawner` in `battlefield.tscn` — and since the whole field shares z 0, tree order put them on top of everything. Blocked by a structural issue: `LaneField._draw()` painted the **opaque page and the props in one canvas item**, so "behind the rocks" and "behind the paper" were the same layer. Page is now split onto a `PageBackdrop` child at z −2 (`_paint_page(target)` — draw calls only affect the item currently drawing, so the child calls in and passes itself, the same trick `LaneForeground` uses in reverse). Layers are now: page −2, **effects −1**, props/units 0, fog 20, border decor 21. Both `queue_redraw()` sites go through `_redraw_field()` so the page follows a layout change.
- **HOW TO PLAY trimmed.** THE RUN is one line per step; hero cards now use `Hero.ROLE_DESCRIPTIONS` — the exact prep roster string — instead of a second, longer write-up that had to be kept in step. Five enemy cards → three (one "THE SWARM" card covering melee/ranged, portal, and a **`?` for the villain** so the boss stays a surprise — `glyph` entries render as text in an identically-sized box). Four hazard cards → two (HAZARDS hurt you, OBSTACLES block you, now including shots). `BODY_HEIGHT` 720 → 580, since that value is a `ScrollContainer` *minimum* as well as a cap.
- **Prep menu text fitting.** Measured, not eyeballed: at SIZE_TINY the widest real price (`Buy Lv10 — 240g`) needed **207px** against a skill node's 194 usable, so the card was forced past `NODE_SIZE` and off the grid pitch `COL_SPACING` positions against. New `UIStyle.compact_button()` (12px sides vs the theme's 22, and 12px top/bottom **up** from 10, because Caveat Brush's descenders overshoot its reported descent) brings it to 160. The UPGRADE ABILITIES/STATS buttons had a hardcoded 230×116 box against 121px of text — their size is now measured from the live font and their label stack is inset to match the stylebox margin (a Button is not a container, so an anchored child ignores it). The drag instruction beside the Duo boxes is now a gold callout with the action on its own line.
- **itch/web build hygiene.** `build/` sits inside the project, so Godot was importing its own previous web output back in as project assets (`index.*.png.import`) and packing them into the next build. Added `build/.gdignore`. Fresh Web export at `build/web/` + `build/SemiSecretWars-web.zip` (34.8 MB, `index.html` at zip root).
- **Known gaps:** **`DeployController` crashes with a group of >2 heroes** — `_positions_for_group()` returns at most 2 positions but `_draw` (line 395) and `_flatten` (line 131) index it by `group.size()`. Fires when `_compute_duos()` hits its documented fallback and dumps everyone into Duo A, i.e. whenever `duo_pairings` is empty or stale (reproduces via `debug_level2.tscn`). **Pre-existing, not from this session; spun out as its own task.** Also: `debug_level2_boot.gd` now stops at the reshuffle overlay waiting for a click whenever pairings are set, same as it already did for boon picks.
- **Next:** playtest, in this order — (1) that the battlefield still has paper behind it (the page split is the one change that could break rendering outright), (2) the Duo reshuffle overlay and the rebuilt Ultimate cards, (3) prep-menu and HOW TO PLAY layout at real size now the font is taller, (4) Berserker's distance from the lair, (5) whether blocked line-of-sight makes ranged units dawdle in level 2's rock density.

## Previous Milestone

**Audio pass, sprite-derived palette, settings menu, run persistence, deploy-flow rework (2026-07-26)** — Built from Designer direction across one long session. **Not verified in-engine at all** — no Godot on PATH this session, so every item below is static-review only. Treat the whole entry as needing a playtest before it's trusted.

- **Settings menu + audio buses.** New `AudioSettings` autoload creates **Music** and **SFX** buses at runtime (not via `default_bus_layout.tres` — that resource loads before autoloads and silently falls back to Master-only if it fails to import, which would leave every `player.bus` assignment pointing at a missing bus). Master/Music/Effects volumes persist to `user://settings.cfg`, deliberately **not** `save.json`, since `full_reset()` wipes that and losing volume on a new game would be a bug. `SettingsPanel` (built on `ConfirmPanel`'s pattern) is reachable from title, prep and battle, plus Escape. It **pauses the tree and restores the previous paused state** on close — so opening it over a level-up pick doesn't resume the battle underneath; the unpause lives in `_exit_tree` so any route to the node dying restores the tree.
- **All three menu themes now loop and survive pause.** Found while adding the settings panel: the panel pauses the tree, and a `PAUSABLE` AudioStreamPlayer stops dead — so opening Settings silenced the very music being tuned. Title/prep players are now `PROCESS_MODE_ALWAYS`, routed to the Music bus (prep's was never routed at all), and MP3-looped so neither screen falls silent while sat on.
- **~15 new SFX wired**, each with its own cadence rule rather than one shared convention: ability callouts rate-limited on seconds (Ensnare 6s, Rally 9s); **Thundaar's stomp pound on a COUNT (every 2nd stomp), not a timer** — cooldown boons push Stomp to ~2s and a 5s gap went *quieter* the faster he stomped; minion deaths on a **static** shared timestamp (a minion dies once, so a per-instance timer would never suppress anything and a swarm wipe would fire 30 grunts). `Seismic_Pound` and `Searing_Burn` were **PCM-analysed to locate their takes** — the former holds 4 impacts of which one overlaps the Designer's shout region and is excluded; the latter is 64.8s of near-silence around a specified 3.551–4.542 slice that measures ~−24 dBFS, far under the rest of the SFX set (**flagged: may need a positive `volume_db` or a normalised source**).
- **Palette re-derived from the sprite art.** Sampled the actual PNGs into a 12-entry pigment set (`UIStyle` PAPER/SOOT/EMBER/NAVY/CANARY/FOREST/BARK/GRAPHITE/LIME/LILAC/CRIMSON/VIOLET); every palette entry, hero identity colour, role colour, status ring, ability flash, objective banner, blood stain and fog tint now derives from one of them. **Hero colours had drifted badly** — Artemis was pink but is drawn forest green; Warden was teal but is drawn brown bark. `VIOLET` is now reserved for the enemy side, so the poison lake, villain lair ring and Slow Zone read as enemy-owned (the Slow Zone was previously drawn in the same blue as friendly UI accents). `DuoSynergies` was **deleted** once its last reader (the battlefield's "DUO A: <name>" banner) went; the generic Duo Bonus mechanic in `Hero` never depended on it.
- **Damage/status feedback moved onto the sprites.** The white hit-flash circle and the status ring were both sized off `body_radius` — the *hitbox* — while sprites draw at up to 2.34× that, so both read as shapes floating near the character rather than on it. Both are now tinted redraws of the sprite itself through a shared `BattleFX.draw_unit_sprite(tint)`, overscaled 12% so the colour spills past the silhouette (the art is mostly black linework; the halo over bare paper is the part that actually reads). Status tint pulses and is much weaker than the hit flash, and draws **under** it, so a stun can't swallow the damage feedback.
- **Duo Ultimate aiming (`DuoAim`).** Seismic Advance and Verdant Path swept a hard-coded +X regardless of where anything was; they now score 24 directions over the full 360° (a swarm behind the party deserves a backwards stomp) weighting spawn points 3× and alerted villains 5× a minion, counting every (circle, target) overlap so a dense column beats scattered clips. Same scorer places **all three clone abilities** — clones are pinned decoys, so spawning beside the caster meant taunting whatever wandered past. Falls back to the old behaviour when nothing is worth aiming at.
- **Run persistence.** A cleared level now writes `user://run.json`; CONTINUE resumes straight into the battlefield. Deliberately narrow: **one checkpoint (level clear only)**, and the file is deleted on every run-ending outcome *before the results screen is readable*, so a defeat can't be undone by quitting. Abandoning clears it too. Consequence to confirm: while a run is resumable the prep menu is unreachable except by abandoning, so mid-run gold can't be spent.
- **Deploy flow reworked.** Deploy now runs **before** the boon picks, and each Duo's pick fires on *its own arrival* — a delayed second Duo picks when it lands, not 10 seconds early. The teleport-in is held until the pick resolves, with `DeployController` outliving its own commit to keep drawing placed hero sprites as markers, so boons are chosen against the real formation. Pre-deploy hero cards now render through `HeroPanelUI.update_display` itself (not a parallel layout) so they are literally the same card. SWAP ORDER button and the running "DEPLOYMENT — …" hint removed.
- **Volatile Duplicates** detonate on **contact** (previously only when hit, so they had to survive a full attack wind-up) with the fuse cut 6s → 2s; that number now means "nothing reached it" rather than a taunt window. **Note: the "Long Fuse" mod (+3s, 75g) is now a 2.5× extension rather than 50% — needs re-pricing or re-wording.**
- **Clones take no outside help** — implemented as no-op boost overrides *on `HeroClone`* rather than filters at each buff source, since clones sit in the `"heroes"` group precisely so everything party-wide finds them. Debuffs still land.
- **Notebook grime (`PageMarks`)** — scribbles, ink stains and shrunk existing smudge sprites, **fixed-seed on menus** (a page doesn't rearrange itself, and `_draw` re-runs on resize) and **re-seeded per battlefield load**. Menus keep marks and props out of the 0.20–0.80 UI column.
- **Also:** coloured logo/button art swapped in; HP bars grade green→yellow→red via two lerps through CANARY (a single green→red lerp passes through muddy olive); Gold/XP emphasised on both screens; hero stat block gets a panel and synthetic-bold numbers (`FontVariation`, since DrawFont ships one weight); Abandon Run + Settings moved top-right; win/defeat stingers stop on leaving (they're parented to the scene root, which survives `change_scene_to_file`).
- **Known gaps:** `exploding_clones` and `roaming_clones` have no cast SFX; the Click_Hero sound was requested but never landed in `assets/` (hook point identified in `BattleHUD._on_hero_panel_clicked`); `BattleManager._end()` still has no re-entry guard, so a simultaneous villain-death and party-wipe would double-award gold — pre-existing, flagged, not changed.
- **Next:** playtest. Priority order: the deploy→boon reorder (biggest flow change), the palette on every screen, `Searing_Burn`'s level, and `DuoAim`'s weights.

- **Found: collision circles were paying for transparent padding.** `_collision_radius()` spanned the sprite's *longest image edge*, so a tall character's collision WIDTH was set by his height (Thundaar's circle was ~1.4× wider than he is) and padded exports paid for empty pixels — `Berserk_Minion_1.png` is 59% empty on its long edge, and its `sprite_scale` of 3.6 looks like compensation for exactly that, which multiplied the waste.

Ellipses reuse the existing circle math through a directional radius — the same trick `_lake_radius_toward` already used — so `obstacles` stays `Array[Vector3]`, there is no ellipse solver, and the change is confined to `Combatant._collision_radii()` plus `LaneField`'s three collision entry points. Thundaar 67 → 41×50, Artemis 67 → 35×57, Berserk minion 50 → 15×18.
- **The safety invariant: every footprint derives from the AUTHORED radius, never the drawn size**, so an oval can only reshape a blocker and never grow one (`rx, ry ≤ radius` always). That is what keeps every already-validated layout valid. Verified across all 9 unit sprites and all 42 obstacles in the three levels.
- **Walkability re-verified.** No BFS harness existed (that check had always been manual); wrote one that reads the `level_*_layout.tres`, derives each obstacle's oval exactly as `LaneField._footprint_for` does, and floods deploy→lair per lane using the real ellipse test. **All three levels clear both lanes.** Battlefield runs clean headless (the only exit warnings are a pre-existing menu-MP3 leak, confirmed by reproducing them independently).
- **Deliberately NOT done, with reasons:** *scenery* got no footprint because it has no collision at all (draw-only — walking through a smudge is correct per ART_BIBLE); *tall props* get a flat ground footprint at the trunk rather than an art-hugging oval, because the canopy is meant to overhang so units path around the trunk.
- **Known trade to watch:** spawn gates block at authored radius 44 but their portal art draws at 176px, so art already dwarfed collision there and the oval (~28×37) widens that gap slightly. Took the safe side since 44 is what layouts were cleared against. If heroes visibly overlap the portal art, normalize the gate's oval so its long axis stays 44 instead of shrinking below it.
- **Next:** playtest the feel — Stage 2's swarm loosens most. `SpriteFootprint.COVERAGE` (0.85) is the single knob and scales every unit and obstacle at once, so treat it as a balance number, not a visual tweak. Cropping the over-padded PNGs before further tuning would mean one feel shift to evaluate instead of two stacked.

**Duo system: explicit pairing, leader/follower choice, named synergy identity, targeting fix (2026-07-20)** — Built, Designer-confirmed working in-session (not yet a full engine/CLI verification pass — see flags below).
- **Duo Bonus (replaces Synergy + Formation):** the old opportunistic "any nearby hero" Synergy (+15% dmg/−0.3s CD/+25% XP) and role-based Formation proximity bonuses were unified into one system — `Hero._update_duo_bonus()` — active only when a hero has a *confirmed* Duo partner (`GameState.duo_pairings`) alive and within 200px (`DUO_DISTANCE`). ## Demo Scope

**Run-as-a-chain loop (current direction):** prep (draft party + priorities, buy permanent ability mods with gold) → **Level 1**: deploy on a *fixed* field the persistent fog gradually maps → auto-battle authored gates' escalating swarm, leveling up in-run via boon picks, one focus-ping to command the party → find and beat the dormant-lair villain → **chain into the next level** carrying HP/boons/levels (the dead stay dead) → repeat until a wipe → back to prep at Level 1 with gold + a better-mapped world. Roster: Thundaar, Artemis, WARDEN, BEACON. Levels 1–3 (Dark Mage / Berserker / Mech Robot), all authored. 2D isometric, player zoom. Two currencies: **XP** (in-run boons, reset each run) and **gold** (permanent ability mods). Core loop proven end-to-end in-engine.
